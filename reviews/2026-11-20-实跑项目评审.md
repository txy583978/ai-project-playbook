- **复现**：
  ```powershell

    Select-String -Pattern "demo123456","demo_operator","manager123456","VITE_DEMO_HINT" -SimpleMatch
  ```

- **保留理由**：作为「构建产物里 grep 敏感值」的检查动作；演示账号本就明文写在 `seed.py`，藏 `.env.development` 不改变其公开属性，真正红线是 `backend/.env`（含数据库密码、JWT_SECRET）不进库。

### 第二轮：排序增强与两个盲区复现（2026-11-20）

- **时点**：第 11 步第二轮回跑，验收通过后按需补 Should#2 排序。
- **改前**：Top 榜仅默认销量降序；`query_log` 无排序列；去重键不含排序；R2 回溯后测试 92 例。
- **改后**：
  - 入参 `sort_by`（quantity / name）、`sort_order`（desc / asc）下推 SQL，次级键取 `Product.id` 稳定排序；
  - `query_log` 加 `sort_by` / `sort_order` 两列，纳入日志写入与 5 秒去重条件；
  - 前端列头可点击切换、带方向指示，首屏默认行为不变；
  - 测试 **97 passed**（新增全集 42 + 排序 / 去重守卫 5），业务行 **452 语句 0 miss = 100%**；`smoke.py` 真实 HTTP **10/10**；真实库 `ALTER` 补列后 seed 重建 79 笔 paid，手工核对默认销量降序 / 销量升序 / 名称升序三种顺序与预期一致。
- **复现**：
  ```powershell
  # 测试库全量 + 覆盖
  backend\.venv\python.exe -m pytest -q --cov=core --cov=routers --cov=services --cov=schemas --cov=models
  # 真实库冒烟（先 ALTER 补列、再起服务）
  backend\.venv\python.exe scripts\smoke.py
  ```
- **两个盲区复现**：
  - E16：`create_all` 只建新表、不改已存在表；SQLite 测试库每次重建自动带新列全绿，真实库必须手工 `ALTER TABLE query_log ADD COLUMN sort_by ..., ADD COLUMN sort_order ...`，先补列再起服务。
  - E17：首轮核对三种排序顺序相同，排查为旧 uvicorn 残留占用 8000 端口、新进程退出；停旧进程重启后排序生效。
- **范围变更**：Should#2 拆为「排序本次落地 / 分页延后」（一期唯一列表是 Top 榜、由 `top_n` 控条数，无全量明细列表承载分页）；图表（Could#2）、行级权限（Should#1）维持移出一期，理由与边界记入需求文档 v1.4 与 `docs/增强记录.md`。
